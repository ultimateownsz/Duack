# Duack.Sample.Web

Self-contained Blazor WebAssembly sample for Duack's KNI (web) adapter. No FlatRedBall2
dependency — it drives `Duack.KNI.MediaPlayerMusicBackend` (platform `MediaPlayer`, an HTML
`<audio>` element on BlazorGL) directly with a render-loop timer. The storyline itself is the
shared, engine-free `samples/Duack.Sample.Core` (the same `StoryController` the desktop sample
uses); web cues surface as duck pulses because the web host has no sound-effect backend yet
(see the root `AGENTS.md` known limitation).

## Run

Requires the .NET 10 SDK with the WASM build tools:

```
dotnet run --project samples/Duack.Sample.Web -c Release
```

Then open the launched URL (e.g. https://localhost:5000) and click a button.

> **Browser autoplay:** browsers suspend audio until a real user gesture. "Start story" is
> that gesture — playback starts on the first click. This is documented, not worked around
> silently.

## What it demonstrates

- **The same storyline as the desktop sample, from the same code**: "Start story" kicks off
  the shared `StoryController` (walk → notice → dialog → battle → loop); "Advance" and
  "Restart" mirror Space/R. Scene music switches crossfade through the KNI backend exactly as
  desktop crossfades through the MonoGame one — one shared core, two playback adapters.
- **Manifest-driven discovery**: browsers cannot enumerate directories, so the page fetches
  the checked-in `wwwroot/Content/Audio/audio-manifest.json` (generated by
  `duack scan .../wwwroot/Content/Audio`) and rebuilds the same `AudioLibrary` the desktop
  sample scans live. One button per discovered track plus the auto-built `music`
  bag-shuffle playlist.
- Code-first config via `SampleAudio` in the shared core (no JSON required for the mix itself).
- `MusicPlaylistController` + `MusicManager` driving `Duack.KNI.IMusicBackend` over the
  platform player, including the single-instance fade-out/switch/fade-in crossfade.
- **Story cues as duck pulses**: the web host has no sfx backend, so each cue (notice, dialog,
  hit) pulses the same `sfx` duck source with the same configured hold as desktop's
  `SfxManager` auto-duck — the mix reacts identically; only the one-shot audio is missing.
- Browser settings store wired via `WebPlayerSettingsStore` + `LocalStorageKeyValueStorage`
  (the `Duack.KNI` localStorage seam).

## Content

`wwwroot/Content/Audio/Tracks/` holds OGG versions of the desktop sample's songs
(`overworld`, `battle`, `hospital`), produced from the gitignored desktop WAV masters with
`duack convert`. To keep the tracks at equal loudness, normalize the masters first:

```
dotnet run --project tools/Duack.Tools -- normalize samples/Duack.Sample.Desktop/_masters samples/Duack.Sample.Desktop/_masters_normalized
dotnet run --project tools/Duack.Tools -- convert samples/Duack.Sample.Desktop/_masters_normalized samples/Duack.Sample.Web/wwwroot/Content/Audio/Tracks --all
dotnet run --project tools/Duack.Tools -- scan samples/Duack.Sample.Web/wwwroot/Content/Audio
```

After changing the tracks, regenerate the manifest:

```
dotnet run --project tools/Duack.Tools -- scan samples/Duack.Sample.Web/wwwroot/Content/Audio
```

To swap in real audio, see `samples/AUDIO_ATTRIBUTIONS.md`.
